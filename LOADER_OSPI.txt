Loader-only OSPI acceleration (RZ/N2L RSK, MX25UW51245G)
=====================================================

Scope
-----
Boot ROM still loads the first-stage Loader in 1S-1S-1S. Its boot parameters,
checksum and 0x6000-byte transfer size are unchanged.

SystemInit initializes clocks, Loader data/BSS and the MPU/cache settings.
bsp_copy_to_ram then configures the xSPI0 pins, temporarily switches Flash and
controller to 8D-8D-8D, and copies VECTOR, USER_PRG, USER_DATA and
USER_DATA_NONCACHE. It restores SPI before constructors, POST_C and main.
PN spi_flash_init and its existing QSPI read/program/erase implementation
are unchanged. This does not certify their existing runtime behavior.

Implementation
--------------
The Loader implementation is in system.c, already relocated in its entirety
to BTCM by script\fsp_xspi0_boot.icf. It does not call application code,
the runtime Flash driver, allocation functions or C library copy routines.
No application data or pin configuration tables are needed before relocation.

Configuration: rzn_cfg\driver\loader_xspi_cfg.h.
BSP_CFG_LOADER_OSPI_ENABLE defaults to 1. Set it to 0 (or define it as 0 in
the compiler settings) for an A/B single-line loading measurement.
The implementation is gated to IAR ROM execution with xSPI0 single-line boot.
Enable this option only when booting from the MX25UW51245G OSPI device.
The separate QSPI device selected by CN8 2-3 does not support this DTR mode;
disable the option when booting from that device.
BSP_CFG_LOADER_OSPI_PREFETCH_ENABLE defaults to 1. It enables hardware
prefetch only during DTR copying.
BSP_CFG_LOADER_OSPI_CACHE_ENABLE defaults to 1. It retains the cacheable
0x60000000 source alias and invalidates the four read-only Flash source
ranges before and after copying. Set it to 0 for the non-cache alias.
This option does not change the global CPU D-cache enable bit or MPU.
See the final prefetch-plus-cache A/B measurement below.

Flash: volatile CR2[0] DOPI=1; CR2[0x300] DC=5 (10 read dummy clocks).
Controller: PRTMD=0x3FF, 4 address bytes, EE11 read, 12ED program mapping,
DS shift=8 at the existing 100 MHz xSPI0 clock, matching the reference setup.
RDCR2 uses 4 dummy clocks, per MX25UW51245G datasheet command table p.20,
not the 10 used by the reference application's register-read example.
Volatile CR2 writes have a delay exceeding tW2V=40 ns.
Original mode/DC and controller mapping/timing/bridge settings are restored.
Only volatile configuration registers are written; no Flash sector is erased.

Alignment
---------
The ICF already gives the four source/destination blocks >=4-byte alignment
(vectors: 32 bytes). Source and destination alignment, not just length, is
required for the uint32_t fast path.

Every explicit CPU DTR Flash load is naturally aligned and 32-bit. The
default cacheable source is 0x60000000; cache-disabled source selection
uses its non-cache 0x40000000 alias. Actual external cache-line fills and
hardware prefetch may read more than an individual CPU word request.
The bulk path stores aligned uint32_t words.
MX25UW51245G DTR reads return adjacent bytes in the opposite order from
the SPI-programmed image: the board returned 0x9FE520F0 for SPI word
0xE59FF020. The DTR probe and all copy paths use CMSIS __REV16 to normalize
each byte pair before comparison, word storage or tail extraction.
Unaligned starts and 1-3 byte tails are extracted from an aligned Flash word
and stored bytewise to RAM, without writing beyond the requested segment.
An explicit edge word may include adjacent Flash bytes but never crosses
the 64 MB device boundary. Real cache/prefetch behavior at the physical
Flash end is not board-certified. Segment lengths need no padding.
No odd-address or single-byte explicit CPU load is issued to DTR Flash.

Hardware and validation
-----------------------
The board must provide IO0-IO7, DS and the clock routing for OPI.
RSK schematic D017892_04, page 12, confirms that CN8 selects between TWO
physical Flash devices, not between protocols of one device:
  1-2: OSPI_CS, IC19 MX25UW51245G, 64 MB.
  2-3: QSPI_CS, IC21 MX25UR51245GMI00, 64 MB.
Pin 2 is the common OQFLASH_CS0 signal.

Downloading with CN8 2-3 programs the QSPI device, not the OSPI device.
Moving CN8 after download therefore does not expose the same image to
8D-8D-8D reads. Do not use live jumper switching as a boot/test procedure.
Program and verify the intended image on IC19, with CN8 1-2 throughout,
using a compatible programmer/Flash loader. Then validate Boot ROM SPI
startup, Loader DTR copying, and the return to SPI on that SAME device.
Unattended cold boot and reset during DTR remain unverified. Controlled
hardware-reset measurements are recorded below.
Do not place breakpoints that require reading Flash during the interval
where Flash and controller protocols differ.

Debugger variables (Loader BSS):
  g_bsp_loader_ospi_stage: 1=entering, 2=DTR/copy, 3=restoring, 4=SPI restored.
  g_bsp_loader_ospi_copy_bmcfg: actual copy-phase bridge/prefetch settings.
  g_bsp_loader_ospi_copy_source: last aligned word in the last nonempty copy.
  g_bsp_loader_ospi_copy_sctlr: CPU SCTLR before the payload window.
  g_bsp_loader_ospi_error:
    0=none, 1=poll timeout, 2=source outside Flash, 3=controller not SPI,
    4=Flash not SPI, 5=DTR CR2 mismatch, 6=DTR mapped-read mismatch,
    7=restored CR2 mismatch, 8=restored SPI mapped-read mismatch, including
    the cached/noncached last-word check when cacheable sources are enabled.
Errors invoke the BSP unrecoverable-error hook and stop; no silent fallback.
The mapped-read probes compare the first vector word before/after switching;
they are not a full application-image integrity test.

Before accepting on hardware:
1. Confirm stage=4, error=0, restored PRTMD=0, normal entry to main and PN.
2. Compare all four RAM segments with the downloaded image.
3. Test PN persistence, single-byte updates and firmware-update paths in SPI.
4. Compare cold-boot Flash-copy duration with enable=0 and enable=1, then
   measure the actual PN FSU endpoint. Do not infer an eightfold speedup:
   ROM load, protocol-switch overhead and PN initialization remain.
5. Test power cycles and warm resets, including a reset during DTR loading.
   A reset that leaves Flash in DTR without resetting Flash may prevent the
   Boot ROM SPI load. Recovery then requires a Flash hardware reset/power cycle.

Host/emulation checks cannot validate pin routing, DS timing margins,
unattended boot or the PN FSU time requirement.

Prefetch plus cacheable-source A/B validation (2026-10-21, current version)
-------------------------------------------------------------------------
Both final variants enable DTR, hardware prefetch, 100 MHz xSPI0 and
10 dummy clocks. CPU global D-cache and MPU configuration are unchanged.
BSP_CFG_LOADER_OSPI_CACHE_ENABLE selects the Flash source alias:
  0: noncache 0x40000000, without the new source-cache maintenance.
  1: cacheable 0x60000000, with paired source-cache invalidation.
The final retained default is 1. REV16 and exact-length RAM writes remain.
There is no DMA, compiler optimization-level or runtime SPI/NVdata change.

New BTCM-local helpers in system.c:
  bsp_loader_ospi_invalidate_source(source, bytesize)
  bsp_loader_ospi_invalidate_sources()
They follow BSP address-based maintenance: get D-cache line size from
CTR.DminLine, align the source down, use __set_DCIVAC for each intersecting
line, and issue DSB before/after. Zero size does nothing; illegal Flash
ranges report error 2. Only read-only Flash sources are invalidated, never
all D-cache or dirty destination RAM. Maintenance covers the four linked
source ranges, not all 64 MB.

After DTR probe, invalidate old SPI source lines before enabling prefetch
and sampling payload_begin. After payload_end, disable/flush prefetch,
isolate the bridge and invalidate DTR source lines before restoring SPI.
After restoring SPI, the CPU compares the last copied source word through
cacheable and noncache aliases; a mismatch reports error 8.
The actual final probe address is 0x60152D08, SPI word 0x00302E30, which
differs from its DTR raw byte-pair ordering.
